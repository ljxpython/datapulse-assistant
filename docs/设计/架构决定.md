## 一、轻量架构决策记录 (ADR)

### ADR-01: 数据库连接与执行引擎选型 (精简剔除 DuckDB · YAGNI 决断)
- **决策**：**直接连接目标真实数据库（MySQL / PostgreSQL / SQLite），坚决剔除 DuckDB！**
- **理由**：
  1. **执行主权**：核心业务是用户提供真实数据库连接，只读 SQL 直接在目标数据库执行，无需中间多余的嵌入式引擎；
  2. **内存极简**：剔除 DuckDB 后，后端无需占用 1GB 内存预算，常驻内存骤降至 150MB 以内，完美适配 `sshmy1` 与 `sshmy2` 的紧凑内存环境；
  3. **架构收敛**：统一采用 `SQLAlchemy` + 异步驱动（`aiomysql` / `asyncpg` / `aiosqlite`），代码极度轻量直观。
- **可逆性**：不可逆（数据层架构收敛）。

### ADR-02: 只读安全沙箱与三权分立 (One-way Door)
- **决策**：采用 **Python `sqlglot` AST 解析 + SQLite/DuckDB URI `?mode=ro` 只读连接池 + `LIMIT 500` 强行包裹**。
- **理由**：
  1. 正则匹配关键字（如正则替换 `DROP`）极易被注释绕过（如 `SELECT /* DROP */ ...`）；
  2. AST 语法树解析能 100% 确认根语句类型为 `Select`，彻底封堵 SQL 注入与数据被篡改的风险；
  3. 物理连接只读模式作为第二道底线防御。

### ADR-03: 前后端流式通信协议 (Two-way Door)
- **决策**：采用 **HTTP POST 建立请求 + Server-Sent Events (SSE) 协议** 流式回传。
- **事件协议规范**：
  - `event: thinking`：推送大模型思考推理片段
  - `event: sql`：推送生成的规范 SQL 代码
  - `event: execution`：推送只读沙箱执行状态与耗时
  - `event: data`：推送查询结果前 100 行数据与元数据列
  - `event: chart`：推送推荐的 ECharts Option JSON
  - `event: summary`：推送数据洞察文字总结
  - `event: error`：结构化错误对象 `{ code, message, stage }`

### ADR-04: 前端交互形态与视觉定调 (One-way Door)
- **决策**：用户正式拍板采纳 **方案 A：Notion / Hex.tech 交互研报画布流 (The Clean Canvas)**。
- **理由**：
  1. 彻底打破传统左右死板分栏和“深色监控大屏”带来的沉重压抑感；
  2. 采用自上而下的麦肯锡研报流，居中 Perplexity 提问岛，高管洞察 ➔ 杂志级平滑面积图 ➔ 明细数据透视；
  3. SQL 逻辑降噪收敛至右上角审计抽屉，兼具极客深度与业务友好度。
- **可逆性**：不可逆（One-way door，前端组件拓扑强绑定）。

### ADR-05: 多轮对话组织与报告归档机制 (One-way Door)
- **决策**：
  1. 多轮连续追问采用 **Notebook / Notion 瀑布流 Block 追加模式**，画布向下延展形成完整分析长卷；
  2. 严格贯彻三权分立：日常分析仅在内存与会话缓存维护，仅当人类显式点击“归档报告”并二次确认后，后端才将报告写入物理磁盘 `reports/` 目录；
  3. 报告导出支持 Markdown 物理文件存档与浏览器标准 A4 PDF 打印。
- **理由**：保证连续思维心流不被打断，同时守死写盘安全底线。
- **可逆性**：不可逆。

## 二、数据流矩阵 (Data Flow Matrix)

| 输入源类型 | 后端解析模块 | 存储介质 | 读路径 (Text-to-SQL) | 输出产物 |
|---|---|---|---|---|
| **.csv 文件** | Pandas / DuckDB `read_csv_auto` | 内存 DuckDB 临时表 | 生成 DuckDB 方言 SQL | 表格 + ECharts 图表 |
| **.sqlite 数据库** | `sqlite3`只读连接 | 本地 `.sqlite` 物理文件 | 生成标准 SQLite 方言 SQL | 表格 + ECharts 图表 |
| **.duckdb 数据库** | `duckdb.connect(read_only=True)` | 本地 `.duckdb` 物理文件 | 生成 DuckDB 方言 SQL | 表格 + ECharts 图表 |

## 三、三权分立系统架构拓扑

```
[ 用户 (Human) ] 
       │ 1. 自然语言提问
       ▼
[ Pi Agent (LLM 决策层) ] ───(生成 SQL 草稿)───► [ 后端 AST 只读沙箱 ]
                                                       │
                                          2. 校验通过且注入 LIMIT
                                                       ▼
                                             [ 只读数据库连接 ]
                                                       │ 3. 产生查询数据
                                                       ▼
[ 前端 ECharts 交互看板 ] ◄──(SSE 流式推送)───── [ 洞察生成与图表封装 ]
       │
       │ 4. 人类审查确认无误后点击“归档报告”
       ▼
[ 物理磁盘 reports/ 归档 ]
```
