# DataPulse Assistant —— 业务需求规格书 (docs/需求/需求.md)

> **版本**：v1.0.0 (已由用户签署冻结 · DoR 达成)  
> **设计语言**：**方案 A · Notion / Hex 交互式研报画布流 (The Clean Canvas)**  
> **核心原则**：所有需求均转化为**可反驳 (Refutable) 的工程断言**，拒绝空洞口嗨。

---

## 🎯 核心场景契约表 (Refutable Scenarios)

| 场景编号 | 场景名称 | 触发输入 | 预期正确行为 (Positive Assertion) | 预期错误/拒绝行为 (Negative Assertion) |
|---|---|---|---|---|
| **REQ-01** | **数据源挂载与表结构解析** | 用户选择或上传 `.csv` / `.sqlite` / `.duckdb` 文件 | 后端在 500ms 内提取表名、字段名、数据类型与前 3 行样例数据，前端顶部以极简药丸徽章展示当前挂载状态 | 文件损坏、权限不足或格式不支持时，立即返回 HTTP 400，严禁静默解析成空表 |
| **REQ-02** | **自然语言转安全只读 SQL** | 用户在居中提问岛输入分析需求（如“统计半年度各销售团队成单额与环比”） | Pi Agent 结合 Schema 生成只读 SQL，通过 SSE 流式推送推理解释与 SQL 代码块 | 包含“删除销售表”或 Prompt 注入攻击指令时，模型拒绝生成或沙箱直接拦截 |
| **REQ-03** | **AST 沙箱校验与自动 LIMIT 注入** | 后端接收到待执行 SQL | `sqlglot` AST 解析判定根节点为 `Select`；若未带 `LIMIT`，自动在语法树追加 `LIMIT 500` 节点并在 Read-Only 连接中执行，返回 JSON 数据列与毫秒级耗时 | 检测到 `DROP`, `UPDATE`, `DELETE`, `ALTER`, `TRUNCATE` 或分号多语句拼接时，100% 拒绝执行并上抛 `SecurityValidationError` |
| **REQ-04** | **Notebook 瀑布流研报追加 (用户拍板)** | 用户在同一会话中发起多次连续追问 | 页面像 Notion / Notebook 一样自上而下追加新的“研报 Block”（包含高管大数字、洞察摘要、平滑面积图与透视表），保留整场分析的连续长卷上下文 | 严禁多轮追问时暴力刷白整个屏幕，必须保持平滑追加与页面自动滚动对齐 |
| **REQ-05** | **SQL 审计优雅降噪抽屉 (用户拍板)** | 用户或技术人员点击右上角 `[ 审查 SQL 逻辑 ]` | 以轻量侧边抽屉或 Modal 弹窗展开，展示格式化 SQL、AST 只读校验标记、执行耗时与一键复制按钮 | 默认状态下主研报画布严禁堆砌大段技术代码，保证高管阅读体验纯粹干净 |
| **REQ-06** | **三权分立报告归档与 PDF 导出 (用户拍板)** | 用户点击“归档本轮报告”或“导出 PDF” | 1. 点击归档时弹出人类确认 Modal，确认后落盘写入本地 `reports/` Markdown 文件；<br>2. 点击导出时调起原生打印流，生成适合 A4 纸张排版的无损 PDF | 未经用户手动点击确认前，后端严禁擅自写入磁盘；纯会话仅在内存与会话日志中维护 |

## 🛑 明确非目标 (Non-Goals)

1. **不做多租户与公网复杂鉴权**：第一阶段聚焦企业内部与本地极速分析，不搞复杂 SSO / OAuth2；
2. **不做任意 Python 脚本直接执行**：禁止大模型生成并执行任意 `eval()` / `exec()` Python 代码，所有分析计算收敛至 DuckDB / SQLite 引擎；
3. **不做写事务与分库分表**：专注 OLAP 只读分析，不承担 OLTP 高并发分库分表写入。
